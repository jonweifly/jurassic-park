# 场景与动作优化 / 3D 资源制作规格

2026-09-19 · Godot 4.4.1 · macOS GL Compatibility · 目标：统一的风格化丛林生存 RTS。

当前是可玩的 6.5 规则复刻原型，尚非原版美术的一比一还原。地形与布置来自已核查的候选地图数据；人物、恐龙、建筑、树木仍为原创几何占位件。此文区分本轮代码改进、现有资源限制，以及正式资源的制作要求。

第二轮状态：静态树林已按空间区域合批，并加入幸存者被树冠遮挡时的局部淡化；正式模型适配层已完成，工具和携带物可配置。下文第一轮资源规格继续适用；新的接口和性能证据见 [模型接入与第二轮记录](model-integration.md)。

| 水面 | 与地面共用材质 | 独立蓝绿水面材质、动态波纹法线与高光 | 岸边泡沫、浅水深浅过渡、水生植被、倒影；本轮没有真实折射或流体模拟 |

| 采集 / 施工 | 共用攻击动作；持续施工没有完整循环；声音与动作各自计时 | 可编辑的伐木、挖掘、施工、搬运、搬运待机动作；斧/镐/锤、木材和矿石独立携带物；落点碎屑；采集音效和资源在触点同步，之后保留 0.25 秒收势 | 肩肘腕、髋膝踝骨骼、握持和脚底接地；正式工具和携带物模型 |
| 行走 | 瞬间达到固定速度；每帧最多跨一个路点，转弯时丢距离 | 短起步加速、连续消费路段剩余距离、平滑朝向、动画速率随实际位移变化、地形贴合 | 精细身体碰撞半径、群体避让、圆弧转弯、脚部 IK、根运动适配 |
| 碰撞 | AStarGrid2D 导航，无独立身体碰撞 | 移动段采样检查阻挡格及斜角，避免大时间步穿过封路；保留动态门和建筑格网 | 当前仍为 2 米格网：大型恐龙没有独立体积导航，不能宣称已解决窄缝和单位重叠 |
| 镜头 | 固定方向、固定插值系数、无跟随与旋转 | 时间相关平滑、相对镜头平移、旋转、俯仰、缩放、跟随、复位；低角度沿镜头臂采样地形；小地图视框跟随朝向 | 树木/建筑近镜遮挡、悬崖附近更完整的镜头形体碰撞；保留正交 RTS 视角 |

为了避免影响游戏规则，环境细节使用独立随机种子，不消费刷怪随机数；没有改恐龙感知范围、刷新组数、噪声距离和资源返送规则。采集加入收势会让单次往返略长，这是动作衔接调整。基础移动速度仍沿用原值。

## 统一风格

采用风格化、适度写实比例的生存 RTS：轮廓清楚、材质偏哑光、植被深浅分层；冷色树林与暖色营地形成方向感。避免写实高模人物搭配球形树冠，也避免每个建筑采用不同程度的卡通夸张。

- 主要颜色：深林绿 `#405936`、苔草灰绿 `#82916a`、木材棕 `#89653f`、帆布沙色、低饱和青灰金属。玩家高亮保持淡薄荷绿，危险提示保留暖红。
- 小比例屏幕表现优先：人物头肩、恐龙头尾、帐篷屋顶和塔的轮廓必须从默认视角可辨认。材质细节不能替代轮廓差异。
- 先完成“幸存者 + 迅猛龙 + 1 棵树 + 帐篷”的同场景样板，再扩展其余资源，避免整套制作后才发现风格不统一。
- 当前占位人物约 2.2 米；正式人物建议 1.8–1.9 米。替换前需统一工具高度、相机近景和目标标记，不能只缩放可见网格。

## 模型与材质交付规范

1. **文件**：提供 `.blend` 源文件、`.glb` 导出文件、贴图源文件和预览图；保留作者/来源/授权信息。游戏内使用原创或取得相应授权的资源。
2. **尺度**：1 Godot 单位 = 1m；导入后 Y 向上；角色正前方与现有逻辑保持 **+Z**；原点在脚底/基座中心，应用缩放，禁止负缩放。Blender 到 glTF 的轴转换以 Godot 中的导入结果验收。
3. **层级**：一个稳定的根节点，Model 下放可见模型；人物通过 Skeleton3D / BoneAttachment3D 暴露 `hand_r_tool`、`backpack`、`cargo`、`muzzle`；建筑暴露 `work_point`、`door_pivot`、`weapon_pivot`。显示模型不拥有资源、伤害和寻路逻辑。
4. **材质**：使用 PBR metallic/roughness，默认 Roughness 0.65–0.95，金属仅用于实际金属件；BaseColor 无烘焙硬阴影。法线用 OpenGL +Y；AO / Roughness / Metallic 可打包 ORM（R/G/B）。透明叶片优先 alpha scissor，避免大量透明排序层。
5. **贴图**：人物/大型恐龙 2048，常规建筑 1024–2048，植被共享 1024–2048 图集，工具 512–1024；同等视觉效果优先共享材质。提供 mipmap，检查叶缘黑边。当前兼容渲染器不依赖屏幕空间或体积效果才能正确显示。
6. **LOD 与碰撞**：人物和恐龙至少 3 档网格；远景骨架数量也要控制。建筑独立简化碰撞；树木只阻挡树干区域；大型恐龙先定义胶囊/圆形半径再定导航通路。渲染模型与导航网格分离。
7. **性能初始目标**：1280×800、默认镜头 60fps；目标机器实测后再确定预算。树林要按空间分块实例化，同一资源避免拆成十几个独立网格；树木被砍后必须同步更新实例、视野和导航。

## 动画规格与接入

当前没有肘、膝等完整关节，旋转几何件只能改善节奏；无法得到自然握持、脚掌滚动和身体重心转移。最终动作应单独制作，或选择能合法使用且骨架可重定向的动作库，再逐个校正工具接触。

| 动作 | 时长 / 频率建议 | 关键接触要求 |
| --- | --- | --- |
| idle | 2–4s 循环 | 呼吸克制；脚掌不漂移 |
| walk / run | 0.6–1.0s / 0.45–0.65s 循环 | 脚步标记 left/right；按实际水平速度调动画速率；不能用播放速度掩盖脚滑 |
| chop / mine | 当前适配 1.35s，触点 1.10s，收势 0.25s | 抬臂、躯干蓄力、落点、收势；斧刃或镐尖落点、声音和碎屑一致；资源只由 Worker 结算一次 |
| build / repair | 当前循环 0.90s，触点 0.65s | 锤头击中工件；循环自然；维修资源仍按既有逻辑计时，不能在动画回调重复扣除 |
| carry / carry_idle | 0.65–0.9s / 2–3s | 双臂托住携带物；挂点稳定；站立时不继续踏步 |
| attack | 依武器/物种 0.4–1.2s | 动画触点与已有攻击冷却统一；本轮仍保留旧战斗结算节奏，正式动画接入时专项校验 |
| turn / hit / death | 0.2–0.6s / 0.2–0.5s / 0.8–1.8s | 左右转向、打击反应；死亡不循环，尸体停在终帧；奖励仅结算一次 |

导出使用原地动画，不默认把根运动直接叠加到导航位移上；采样建议 30fps。循环首尾姿态一致，禁止未经清理的骨骼缩放和负缩放。接触事件以元数据或命名标记交付，由游戏逻辑统一触发声音/特效。

**模型适配层已在第二轮落地**：`pawn_visual.gd` 已暴露模型根节点、AnimationPlayer、动作名映射、工具/携带物挂点和 PackedScene 配置；Worker、资源返送和 AI 保持独立。骨骼模型仍不能仅替换 `.tscn` 就投入使用，需要配置并验收新模型的动作、挂点、触点、步态和碰撞体积，见 [接入流程](model-integration.md)。

## 验收与本轮证据

- 默认与旋转镜头下，地面点击与角色所在高度一致；平移、跟随和缩放无瞬移；操作 HUD 不下达地图命令。
- 脚掌与地面误差目标 < 5cm，工具接触误差 < 10cm；步态滑移、双手握持、骨骼穿插须在正式骨骼资产阶段检查，当前占位件不宣称达标。
- 同时检查白昼、夜间营火、近景采集、远景树林；未探索敌人不能因换材质而露出。舞动树叶与迷雾必须共用位移规则。
- 导航专项覆盖不同帧率路点距离、末段停车、阻挡格穿越和斜角；仍需后续的大体型/群体拥挤测试。
- 自动回归：规则 39、场景 41、AI 56、新增 polish 26 项；真实岛屿连续遭遇 7 组通过。音频通过真实系统混音器检查 44 项。并非 45–80 分钟全局平衡或多机性能验收。
- 第一轮性能观察约 6.5k 次绘制；第二轮在同场景增加静态树木合批后降至约 1.3k，详细对比与图元开销权衡见 [实测记录](model-integration.md)。不能据此宣称整局稳定 60fps。
- 原生 OpenGL 截图：`godot/captures/polish-before.png`、`polish-after.png`、`polish-night.png`、`polish-rotated.png`、`polish-chop-windup.png`、`polish-chop-impact.png`、`polish-wide.png`。截图工具只修改该次运行，不改变正常开局。

运行方式见 `godot/README.md`。正式资源建议按 P0 样板 → P0 全套 → P1 生物群落与建筑 → P2 演出推进；每轮在实际游戏镜头和碰撞场景里验收。
