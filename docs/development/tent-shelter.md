# 躲进帐篷：庇护与治疗

## 目标

小幸存者走到帐篷里，既能恢复生命，也能躲开恐龙的撕咬。这个需求来自一位看着大人玩的小朋友——他觉得帐篷本来就应该能进去。因此除了规则要成立，**画面上要一眼看懂**：人进去了、在回血、外面的恐龙咬不到他、但帐篷会被咬坏。

## 现状

治疗已经存在，但它不改变任何战斗规则：

- `world.gd:1042` `heal()` 找到最近的、已建成、可寻路到达的帐篷，然后 `worker.assign("heal", ...)`。
- `worker.gd` 的 `heal` 分支在抵达后每秒扣 1 黄金、回一次血。
- 幸存者站在帐篷格子上，但对恐龙来说他和站在空地上毫无区别。
- `world.gd:1067` `near_completed_tent()` 用 2.8 米半径判断"在帐篷旁"。

所以本设计不新增治疗流程，而是给"已经在帐篷里"这个状态加上庇护语义。

## 方案：状态标记，不搬动角色

在 `pawn.gd` 增加 `var sheltered_id := -1`，表示"此人正处于哪座帐篷的庇护中"。角色**留在原地**，坐标不变。

曾考虑把角色真的移到帐篷内部或从场景中摘掉，但否决了：寻路、视野、合作模式的位置同步、以及撤离判定 `coop_session.gd:425` `all_inside()` 全都依赖幸存者拥有真实坐标。移动或摘除角色会同时破坏这四处。状态标记是改动面最小、且不触碰坐标语义的做法。

`sheltered_id` 记录具体帐篷 id 而非布尔值，这样帐篷被拆、被摧毁或失效时能精确判断该驱逐谁。配套 `func is_sheltered() -> bool: return sheltered_id > 0`。

## 进入与离开

**进入**：抵达即进入。`worker.gd` 的 `heal` 分支在"已到达且帐篷有效"时设 `sheltered_id = target_id`。不额外加一步"进入"操作——对小朋友来说，走到帐篷就该是进去了。

**离开**，以下任一条件成立即 `sheltered_id = -1`：

- 玩家下了别的命令（`world.gd:1029` `stop_order()` 及任何新指令）
- 帐篷被摧毁或拆除
- 治疗结束（满血）
- 角色倒下

黄金耗尽是个例外：**人留在帐篷里，只是停止回血**，并提示一次。这是刻意的——庇护是"待在里面"的收益，不该因为没钱就把人踢到恐龙嘴边。这也是与现有 `worker.gd` 行为的唯一冲突点：现在没钱会 `stop_order()`，需要改为保持庇护、暂停回血、只提示一次。

## 恐龙一侧：四处都要改

关键风险是漏改其中任何一处，都会出现"人在帐篷里却被咬死"。四处彼此独立：

1. `dinosaur_ai.gd:211` `visible_target()` 的**常规幸存者循环**——跳过已庇护者。
2. 同函数的**反击分支**（受击后回头咬人）。这一处最容易漏：它不走常规循环，若不加判断，恐龙会隔着帐篷咬人。
3. `dinosaur_tactics.gd:13` `preferred_target()` 的迅猛龙选目标循环。
4. `dinosaur_specials.gd:97-99` 的范围伤害循环。它**绕过** `resolve_strike()` 直接 `survivor.health -= ...`，所以酸液和踩踏需要独立的庇护判断，否则帐篷里的人会被特殊攻击打死。

`dinosaur_ai.gd:409` `resolve_strike()` 也加一道兜底判断，防止已锁定的攻击在对方进入帐篷后仍然结算。

**不需要**新增"改为攻击帐篷"的逻辑。`visible_target()` 末尾已有建筑回退循环，而帐篷就在幸存者所在位置、就在 `session.buildings` 里——恐龙会自然地开始拆帐篷。

## 帐篷会被拆：这是设计，不是漏洞

庇护不是无敌。恐龙会转而攻击帐篷，帐篷耐久归零时里面的人被驱逐到战场上。这让"躲进帐篷"是一个有时限的决定，而不是一个胜利按钮。

帐篷耐久降到 **40%** 时提示一次，让玩家有时间反应。

该提示**不能**复用 `world.gd:87` 的 `defense_notice_after`。那是一个 10 秒全局节流（`world.gd:885` 的提前 return 在提示之前），完全可能把最该出现的这一条警告吞掉。因此庇护警告需要自己的一次性标记，且必须插在那个提前 return **之前**。

合作模式下两人可以躲进同一个帐篷，一只恐龙拆掉它就同时赶出两个人。保留这个风险——它是真实的战术后果，不是缺陷。

## 看得见

小朋友判断机制是否生效，只能靠画面：

- 角色模型在庇护期间隐藏（或明确淡出），传达"他在里面"。
- `coop_replication.gd:97` 已经在按 `health > 0` 控制 `selection.visible`，庇护可见性挂在同一处。
- 帐篷有一个持续的"里面有人"指示，否则角色一消失就像是死了。
- 回血用现有治疗反馈，不新发明一套。

## 存档与联机

**存档**：`sheltered_id` 加入 `save_store.gd:12` 的 `PAWN_FIELDS`，并把 `save_store.gd:3` 的 `VERSION` 从 3 升到 4。必须升版本：`restore_fields()` 无键存在性保护，而 `matches()` 缺键即判定不兼容；靠版本号在 `save_store.gd:85` 提前挡掉旧档，会得到"存档版本不兼容"的正常提示，而不是崩溃。不做兼容垫片。

**联机**：`sheltered_id` 加入 `coop_replication.gd:30` `pawn_packet()`，由 `apply_pawn()` 应用。

**不需要新的联机指令**。`coop_session.gd:343` 的 `valid_intent()` 已允许无参数的 `"heal"`，`dispatch()`（`:368`）已映射到 `world.heal()`。庇护是房主端 heal 流程的结果，天然属于权威方，客户端无法自行声明自己受庇护。

## 测试

- 庇护期间恐龙改拆帐篷，不再咬人——四条路径逐一覆盖（常规、反击、迅猛龙、范围伤害）。
- 帐篷被摧毁后驱逐并恢复可被攻击。
- 黄金耗尽保持庇护、停止回血、只提示一次。
- 40% 警告在防御提示节流生效期间仍然出现。
- 存档往返保留 `sheltered_id`；旧存档被干净拒绝。
- 合作模式下庇护状态同步到客户端。
- 撤离判定不受庇护影响（`all_inside()` 仍看坐标）。
