# 6.5 开局、区域、返送资源与恐龙训练：本地原始数据核对

2026-09-16。仅静态读取 `reference/warcraft-6.5/` 中已下载的汉化修正版候选；不修改游戏，不执行 JASS。该候选带附加作弊脚本，不能视为已证明纯净的官方分发。本文未引用 3.3、6.3 或 6.5.2 数据。

## 关键结论

1. 四区域不是以坐标轴直接四等分，雨林和山地各由两个矩形组成；下面有准确坐标。
2. 初级幸存者的采集技能 A04M：树木每次伤害参数 5，木材携带上限参数 1，金钱携带上限参数 1；“5”不是开局每趟带回 5 木。
3. 恐龙训练场 h00E 不生产 o00K：它的训练单位表为空；o00K 是一只已有 o004 迅猛龙完成伐木训练并离开 h00G 后被替换出来的单位。
4. 沼泽实际将特定建筑的施工进度设为 70%，不是一般意义的速度乘 1.7；升级也直接设为 70%。
5. 化石挖掘场黄金价格继承 ngol；本地没有 ngol 基础 SLK，因此无法仅靠当前资料证明黄金费用为 0。

## 四区域准确触发边界

Warcraft 世界坐标，格式 `(min_x, min_y, max_x, max_y)`。x 向东、y 向北。矩形必须取并集，不要填平矩形之间或中央的空白。

| 区域 | JASS 变量 | 精确边界 |
|---|---|---|
| 雨林南片 | Zo | `(-7520, -8128, -320, -1920)` |
| 雨林西片 | vr | `(-7552, -1888, -1440, 1600)` |
| 山地东片 | er | `(1696, -512, 8032, 1760)` |
| 山地北片 | xr | `(256, 1760, 8000, 7168)` |
| 冰原 | rr | `(-7520, 1952, -160, 7232)` |
| 沼泽 | ir | `(128, -7968, 7968, -1856)` |

证据：[矩形定义](../../reference/warcraft-6.5/war3map.j#L15714)，约 15714–15730 行；[雨林进入与离开事件](../../reference/warcraft-6.5/war3map.j#L17939)，约 17939–17956 行；冰原事件 17967–17978 行；山地事件 17983 行开始；沼泽事件 18124 行开始。

效果的静态证据：

- 雨林对幸存者添加/移除 A02O（`war3map.j:13641`）；A02O 基于 AHab，`Hab1:1:1 = 1.0`、范围 0（`objects.json:11257`）。因此可实现雨林魔法恢复加成，但其单位语义仍依赖原生技能元数据。
- 冰原对电脑恐龙添加 A03W，离开时移除（`war3map.j:13722`）；A03W 的移动/攻击速度参数均为 -0.3，说明写明均减 30%（`objects.json:11941`）。**不是伤害减 30%。**
- 山地 A02N 的 Idef = 3；A02P 的 Cac1 = 0.5，说明为护甲 +3、炮塔攻击 +50%（`objects.json:11272`、`11282`）。各建筑在建造/升级/进入区域时添加技能，存在具体类型条件，不能无条件给每个单位加伤害。
- 沼泽 `Iz` 直接 `UnitSetConstructionProgress(...,70)`，限定 `h006,h00K,h004,h00D,h01H,o003,n000,h00N,h001,h002,h00Y`（`war3map.j:14068`）；事件为进入 ir（18176–18179 行）。`az` 在升级开始时把升级进度设为 70（14048–14053；18163–18166）。若 Godot 从 0 施工，等效剩余时间约为原时长 30%，应保留事件与适用类型差异。
- 另有把施工设为 50 的 Vz，但对应触发器 oA 初始化时被禁用（18167–18171）；不能把这条当成默认启用效果。

## W3E 二进制：本文件可以确认的布局

文件：[war3map.w3e](../../reference/warcraft-6.5/war3map.w3e)，116,568 字节。二进制文件用字节偏移而非行号引用。

| 字节偏移（0 基） | 内容 / 本次读取值 |
|---|---|
| 0 | ASCII `W3E!` |
| 4 | LE uint32 版本 `11` |
| 8 | 主地形 ASCII `Z` |
| 9 | LE uint32 自定义地形标记 `1` |
| 13 | LE uint32 地面纹理数 `9` |
| 17 | 9 个 4 字节地形 ID：Zdrt, Zdtr, Zdrg, Zbks, Zsan, Zbkl, Zgrs, Zvin, cNc1 |
| 53 | LE uint32 悬崖纹理数 `2` |
| 57 | `CZdi`, `CZlb` |
| 65 | LE uint32 宽 `129` |
| 69 | LE uint32 高 `129` |
| 73 | LE float 原点 x `-8192` |
| 77 | LE float 原点 y `-8192` |
| 81 | 16,641 个 7 字节顶点记录；`81 + 129*129*7 == 116568` |

按经典 W3E 布局，7 字节顶点记录为 `uint16 ground_height, uint16 water_height_and_flags, uint8 texture_and_flags, uint8 variations, uint8 cliff_and_layer`。索引按行 `y*129+x`；格子尺寸为 128 Warcraft 单位。

常见解码公式：地面纹理 `byte4 & 0x0f`，坡道 `byte4 & 0x10`，水 `byte4 & 0x40`，悬崖纹理 `byte6 >> 4`，悬崖层 `byte6 & 0x0f`；地面高度 `(ground_raw - 8192)/4 + (layer - 2)*128`，水高度 `((water_raw & 0x3fff)-8192)/4`。**这些是 W3E 格式解释，当前本地没有附带官方格式规范或原生引擎运行结果来独立验证每个标志位；不要把水位高位直接算进高度。**

字节一致性校验：首顶点 `(8300,24576,7,68,0)`；中心顶点 `(8148,8192,1,33,5)`。ground_raw 范围 7168–11339；顶点悬崖层实际覆盖 0–8。水原值 24576 出现 2851 次，其 `0x4000` 高位是明显必须分离的标记。Godot 若用 x/z 平面、北向负 z，需要 `z = -warcraft_y * scale`；不可不翻 y 而导致山地落到右下。

## 木材、金矿与返送

证据：[幸存者 H02Q](../../reference/warcraft-6.5/objects.json#L5592)，`uabi` 包含 A04M；[A04M](../../reference/warcraft-6.5/objects.json#L12554)。字段使用 Warcraft Harvest 的标准解释：Har1=树木伤害，Har2=木材携带容量，Har3=金钱携带容量。

| 采集技能 | Har1 树木伤害 | Har2 木材容量 | Har3 金钱容量 |
|---|---:|---:|---:|
| A04M 初始 | 5 | 1 | 1 |
| A01W | 10 | 2 | 2 |
| A01X | 15 | 3 | 3 |
| A01Y | 20 | 4 | 4 |
| A04V | 25 | 5 | 5 |

技能对象行：A01W 10771、A01X 10789、A01Y 10807、A04V 12597。科技 R00T 完成后由触发替换这些技能，而不只是增加收入倍率（`war3map.j:13187` 至 13249）。例如 R00T 已研究等级为 2 时才由 A04M 换 A01W；不要把科技列表的显示等级直接套成初始技能等级。

返送是“采集 → 携带 → 走回可接收建筑 → 玩家资源到账”的原生 Harvest/Return 行为。升级采集技能的 `auu1` 明确写返送到最近帐篷；帐篷 h002 的 `uabi` 包含 **Argl**（接收金木的原生技能），迅猛龙巢穴 o00M 也有 Argl。不能在砍树动作完成时直接无限加钱/加木，也不应只允许一座帐篷作为唯一返送点。

没有在本地对象覆写中找到完整 Ahar 的基础采矿耗时、Argl 原生实现或 Agld 全部参数，因此“每次固定几秒、接收距离、金矿同时容纳人数”不在已证明范围内。

训练后迅猛龙 o00K 带 **Ahrl**（只伐木），Ahrl 的 Har2 改为 **5**（`objects.json:9343`）；并不是和初始幸存者同样的 1 木携带量。o00K 速度 350、HP 100（`objects.json:2948`）。

化石挖掘场 n000（`objects.json:296`）：基类 ngol，`ulum=10`、`ubld=10`、`uhpm=100`，前置 `h002,h001`。没有 `ugol` 覆写，也没有单独 ngol 原始对象修改记录。**黄金成本仍未能从本地资料闭合。** `A009` 的“拆除扣 10 金”和 JASS 的拆除罚款是另一笔费用，不能反推建造黄金成本也是 10。

## 恐龙训练场、已有迅猛龙与伐木训练

| 对象 | 数据与取得方式 |
|---|---|
| h00D 基础建筑 | 5 金 / 5 木，5 秒，需求发电站 h004；升级列表包含 h00E。`objects.json:927` |
| h00E 恐龙训练场 | **5 金 / 5 木，10 秒，100 HP**，需求 h004；`utra` 明确空字符串，`ures=Ropm`，`uupt=h00G`。`objects.json:965` |
| Ropm 训练恐龙捡起物品 | **5 金 / 5 木，15 秒**，无显式前置。`objects.json:5656` |
| R012 生物学：恐龙伐木 | **50 金 / 50 木**，要求 R00B 等级 4、R00W 等级 1；耗时没有覆写，不能声称为某个固定值。`objects.json:6521` |
| h00G 恐龙训练中心 | h00E 的升级目标；**5 金 / 5 木，10 秒，140 HP**，要求 R012 与 h004。`objects.json:1105` |
| o004 普通迅猛龙 | **12 金 / 12 木，10 秒**，HP 100、速度 350、无物编前置；这是普通龙定义，**不是 o00K**。实际生产列表在 o00M 迅猛龙巢穴 |
| o00K 训练过的迅猛龙 | 无直接生产费用/时间覆写。通过 h00G 训练既有 o004 后触发替换，不是 h00E 里点击直接造出的兵。`objects.json:2948` |

关键触发链：

1. 幸存者 H02Q 进入 h00G，登记 X[player]；支持恐龙进入 h00G，登记 O[player]（`war3map.j:10671` 至 10760）。
2. 一名幸存者与一只可训练恐龙同时在内时启动训练；训练期间检测是否仍在内，否则终止。kP 内等待总计约 **28.8 秒**，由自定义轮询等待 zN 实现，实际帧调度可更长（`war3map.j:10800` 附近；zN 在 3820 行）。
3. 完成只把 R[player] 增加 1，并提示成功；**还没生成另一只恐龙**。
4. 让恐龙先离开 h00G，在卸载命令目标为 o004 且 R>=1 时 `ReplaceUnitBJ(...,'o00K',1)`；然后扣 R、O 并重新开启训练触发（`war3map.j:10891` 至 10927）。
5. h00E/h00G 的训练表均空，不能从 o00K 继承 otau 的原始造价自动造兵。

补充：o00M 巢穴的训练表包含 o004。幸存者死后存在变为 o00D 恐龙、可建巢穴协助他人的分支，并设 o004 上限 2（`war3map.j:10464` 至 10484）。这不是健康幸存者开局通过普通训练场生产迅猛龙的证据。

本轮未穷尽捕获/驯服既有野生恐龙的链路，未补全 ngol、Ahar 等 Warcraft 基础 SLK 继承值，也未运行地图。上述明确数值和状态链可以校准当前开局；未知值需要在实现中保留为待校准参数。
