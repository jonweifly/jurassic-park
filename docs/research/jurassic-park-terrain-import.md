# 6.5 地形布局导入记录

2026-09-16。读取既有候选 `candidate-6.5.w3x`，未运行地图脚本，未提取游戏模型或贴图。候选来源和限制见 [参考目录](../../reference/warcraft-6.5/README.md)。

## 来源与转换

- `war3map.w3e`：129×129 顶点，高度、纹理索引和水位。字段布局及公式见 [开局原始资料核查](jurassic-park-6.5-opening.md)。保持原坐标比例，每 64 魔兽单位对应 1 Godot 单位，北方向映射到负 Z。地面由顶点三角网格构造；悬崖使用相邻顶点连接的斜面近似，不使用魔兽原生悬崖模型和坡道拼接规则。
- 新读取 `war3map.wpm`：头部 `MP3W`，版本 0，512×512 字节通行数据。采用经典位解释：0x02 不可走、0x08 不可建。导航每 4×4 子格合并一格，取中央 2×2 的限制；并非逐子格精确导航。原始地面不可走格不会因伐木而被错误清除。
- 新读取 `war3map.doo`：`W3do` 版本 8、子版本 11，共 6,849 个常规布置条目。读取 ID、变体、位置、旋转、缩放、状态和生命，跨过掉落表，常规记录结束于字节 342,466；总文件 342,490，尾部特殊布置未渲染。
- 识别 3,680 棵树（3,252 阔叶替身、428 雪松替身）和 410 个岩石。模型是 Godot 原创几何占位；保留来源 XY、朝向、缩放，高度采样自导入地表。部分自定义 D00x 装饰尚未解析；不应把已导入实例数称为原地图所有树木/装饰数量。
- 同一个导航格里的树木归入一个可采集组，共 2,991 组。采尽时清除整组，属于当前网格精度的简化；不等同于原版逐棵树的独立碰撞与生命值。
- 区域边界按 JASS 的矩形并集判断，山地和雨林各有两块区域。材质配色、树种替身、纹理混合和程序噪声为原创视觉表达，不是原版美术复刻。

导入工具：[import_reference_terrain.py](../../godot/tools/import_reference_terrain.py)；烘焙工具：[bake_reference.gd](../../godot/tools/bake_reference.gd)。布局输出为 `godot/data/terrain.json`，可编辑场景为 `godot/scenes/reference_island.tscn`。旧临时场景保留。

## 玩法校准

采集与训练来源见 [开局核查](jurassic-park-6.5-opening.md)。当前接入每趟 1 木/1 金返送、可施工挖掘场、5 秒电门切换、沼泽特定建筑从 70% 进度开始、冰原恐龙移速与攻速降低 30%、山地塔/电栅栏/电门伤害 +50%。山地护甲 +3 使用临时的 `damage / 1.18` 曲线；不是完整魔兽护甲类型/攻击类型计算。

尚未接入恐龙训练链、雨林魔法加成或全套区域事件。化石场黄金造价仍是未解析的继承字段，暂用 0 并显式列为待校准。

## 验证范围

实际场景集成检查证明出生点可通过现有导航到达四个区域、鼠标射线拾取与导入高度一致，以及施工、返送、开门后寻路、战争迷雾和战斗没有破坏基础闭环。真实 OpenGL 渲染检查覆盖营地、山地与冰原。

这些检查不证明原图所有洞口、悬崖、路径、所有建筑占地都已精确还原；仍需对照纯净地图与原版实机，细化坡道和子格导航。
