# 《侏罗纪公园》发布平台调研

**调研日期：** 2026-09-30
**项目形态：** 仓库里同时有 Vite/Canvas 网页原型和 Godot 单机客户端（见根目录 `README.md`）。本文把“可以直接上传网页包”和“需要导出或适配后再发布”分开说明。

## 先给结论

1. **最快验证网页版本：itch.io。** 可以自助建立作品页并上传 HTML5 包，适合先收集试玩反馈；不依赖平台精选，运营和流量需要自己承担。
2. **想要网页游戏平台流量和广告变现：CrazyGames。** 适合桌面横屏生存/塔防玩法，但要先做包体、加载速度和 SDK 适配；Basic Launch 没有平台广告变现，Full Launch 才能使用完整 SDK 方案。
3. **做成熟网页发行合作：Poki。** 需要申请和人工筛选，平台会做测试、QA、营销和发行；代价是同一游戏的开放网页版本通常要接受网页独占条款。
4. **国内最现实的入口：TapTap H5/WEB。** TapTap 开发者中心现在明确列出 H5/WEB、Windows PC、Android/iOS 和 Tap 小游戏，并支持个人与企业发布。当前网页原型可以先做 H5 页面；Godot 客户端则导出 Windows 包走 PC 发行。
5. **微信小游戏、抖音小游戏是“适配后”的国内增量渠道。** 它们不是把现有 Vite 网站压缩包直接上传，而是要适配各自小游戏运行时、账号/数据/审核和运营流程。只有在移动端体验和合规资料准备好后再投入。
6. **如果要销售 Godot 单机版，Steam 是更匹配的国际 PC 渠道。** Steam 面向桌面安装包，不是网页托管；需要 Steamworks 入驻、应用配置和 Steam Direct 费用，适合完成度更高的版本。

## 发布前必须处理的风险

### 1. IP 与商标

当前标题和产品表达使用了“Jurassic Park/侏罗纪公园”。这是知名影视/游戏 IP；除非已经取得相应授权，否则不应把官方角色、名称、标识、电影素材或容易造成官方关联的美术提交到任何平台。最稳妥的做法是改成原创恐龙生存公园设定，并全面检查标题、商店文案、缩略图、模型、音效和宣传视频。

### 2. 网页包体与加载

CrazyGames 官方要求初始下载不超过 50 MB，并强调首帧与可玩状态。发布前应运行 `npm run build`，用生产服务器测试首屏、资源路径、刷新和全屏；不要把开发服务器地址提交给平台。Godot HTML5 导出还要单独测内存和移动浏览器兼容性。

### 3. 平台独占与渠道顺序

Poki 的开发者指南明确说明网页独占适用于开放网页门户/聚合站，但 Steam、应用商店和主机仍可保留。若目标是同时运营 itch.io、CrazyGames、TapTap H5 和自有站点，应先选择非独占渠道验证数据，收到 Poki 合作条款后再决定是否签约。

### 4. 商业主体与合规

国内平台可能要求实名主体、隐私政策、未成年人/内容分级、ICP备案或其他提交材料；这些要求会随产品类型和平台政策变化。本文只记录官方开发者入口，不把“能看到上传按钮”当作已经满足上线资格。最终应以 TapTap、微信、抖音控制台在提交时显示的清单为准。

## 建议的发布顺序

### 阶段 A：一周内做可玩验证

- 改用原创项目名和原创素材，生成 30 秒预告图/视频、中文和英文简介。
- 发布 `itch.io` HTML5 Demo，并同步准备 `Newgrounds` 社区页。
- 在自有页面保留反馈入口，记录首局完成率、平均游玩时长、设备和浏览器错误。

### 阶段 B：网页平台发行

- 把网页构建压到 CrazyGames Basic Launch 要求内，验证 Chrome/Edge、4 GB 内存设备、横屏和键鼠操作。
- 首次提交 CrazyGames 时先用 Basic Launch 验证质量；留存和时长稳定后再接 SDK 和广告。
- 如果 Demo 数据好，再申请 Poki。提交前先明确是否接受网页独占及收入分成条款。

### 阶段 C：中国渠道与客户端

- 用 TapTap H5/WEB 做国内玩家测试；如果用户更偏 PC，则同时上传 Godot Windows 客户端建立 PC 产品页。
- 只有在触控、移动端性能和短局循环完成后，才评估微信小游戏和抖音小游戏移植。
- 完成存档、成就、输入设置、安装包更新和版权清理后，再上 Steam。
