# 和朋友一起玩：双人合作预览版

## 准备

双方使用同一份游戏版本。当前提供 Godot 项目试玩包，**还不是免安装的 Windows/macOS 正式发行包**。朋友需要安装 Godot 4.4.1 标准版，将试玩包解压，在 Godot 项目管理器导入 `godot/project.godot`，等待资源导入后按 **F5（运行项目）**。无需安装 Blender、Python，也不需要 Git 仓库权限。

本项目电脑仍可通过原来的“启动游戏.command”启动。

## 同一个 Wi-Fi / 局域网

1. 房主在开始界面点击“双人合作 · 创建 / 加入房间”。
2. 选择标准合作或困难合作，保留端口 `24565`，可设置房间口令，点击“创建房间”。
3. 点击画面顶部的合作状态条，查看房主地址和端口。
4. 朋友进入同一个合作面板，填写房主的局域网 IP、相同端口和口令，点击“加入房间”。
5. 出现“合作 2/2”即可开始。每人独立控制自己的角色和镜头，绿色为自己，蓝色为队友。

系统询问本地网络或防火墙访问权限时，允许游戏在你们使用的网络中通信。访客 Wi-Fi 的设备隔离可能阻止互联。`127.0.0.1` 只用于一台电脑开两个进程测试，不能让另一台电脑连接。

## 不在同一个地方

先通过 Tailscale 或 ZeroTier 等工具让双方加入同一个虚拟局域网，然后用房主的虚拟局域网 IP 加入。确保工具的访问规则允许双方通过所选 UDP 端口通信。

当前没有公网房间码、自动 NAT 穿透或游戏中继服务。无需为了试玩先租游戏服务器，也无需把项目上传到网页游戏平台。

## 合作规则

- 共享木材、黄金、电力、科技、建筑、视野和击杀统计。生命、工作指令、携带资源分别计算。
- 移动、砍树、返送、建造、旋转电门、拆除、研究、箭塔改造和攻击由房主确认并同步。
- 倒下的玩家等待队友救援。队友靠近到 3 米内并且视线可达后，点击“救起队友”，消耗共享的 10 黄金，恢复 35% 生命。全员倒下则失败。
- 撤离时存活玩家需要一起进入 H 圈。倒下的成员不会阻止存活成员撤离。
- 有两名角色时，开局三分钟后，每波增加约一半支援恐龙，最多额外 4 只；沿用存活恐龙总量上限。单机波次不变。
- 双方打开暂停、科技等原有暂停面板都会暂停整局；需要各自关闭自己的面板才能恢复。切换到别的应用不会自动暂停合作局。

## 保存和重连

- 合作存档由房主保存，在 `user://coop/latest.jpc`，和现有单机存档隔离。F5 手动保存，房主原有两分钟自动保存也作用于合作局。
- 当前房主必须存活才能保存。失败或撤离结束后，使用之前的合作存档重试。
- 房主在开始界面选择“继续合作存档并开房”；队友重新加入后取回存档中的第二名角色和携带资源。继续存档时先停止旧工作指令，防止重新加入前自动消耗资源。
- 队友掉线时房间自动暂停，保留角色。队友不退出整个应用，返回菜单再加入，可用当前会话身份取回同一角色。房主可以等待，也可以继续游戏；继续时断线角色仍可能受到攻击。
- 如果队友关闭并重新打开整个应用，当前房间的旧位置仍为之前的连接保留。房主可保存、返回菜单，再“继续合作存档并开房”，让队友重新领取第二个角色。
- 房主退出会结束房间；没有房主迁移，也没有持续在线的独立服务器。

## 分享试玩包

开发电脑执行：

```sh
python3 scripts/package-coop.py
```

输出 `godot/builds/JurassicCamp-Coop-Source.zip`。此包只包含运行项目和说明，不包含 Git、个人配置、存档、建模工具或测试截图。

## 当前验证边界

已使用本机两个独立 Godot 进程通过真实 ENet UDP 验证，包含原生客户端截图。跨两台设备、不同操作系统、家庭路由器及虚拟局域网的实际网络质量仍需实际试玩确认。初版不做客户端移动预测，高延迟网络下发出命令会有等待；画面使用位置插值降低跳动。
